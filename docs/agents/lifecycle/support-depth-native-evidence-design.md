# Packet-bound native evidence integration

Status: proposed; NE-P1 and NE-P2 await maintainer decisions. Design only.
Baseline: staging `51bdfbfa518d8a1ee1a2a596f246ac8629ec287a` (PR #305).
The [evidence contract](../../specs/support-depth-evidence-v1.md) and
[depth contract](../../specs/support-depth-contract.md) remain normative until amended through
reviewed implementation. This document installs no producer, profile or enrollment.

## Outcome

Connect a foreground native UAA execution to the exact maintenance packet, then let the existing
read-only evaluator decide each due obligation. Normal Codex authentication belongs to the
execution environment. Required CI remains credential-free. The completed local smoke stays
completed; its old output cannot be retroactively turned into packet evidence.

PR #305 supplies reusable case identities, session/order/cancellation assertions and sanitized
observations. Its twelve smoke cases are not coverage of every BASE, template, M or classified
effect. Its Git identities are observations, not build attestation; packet binding is null.
The producer below must execute afresh for a real packet with the required reviewed case set.
An ordinary diagnostic command remains useful without gaining maintenance authority.

## Policy recommendations

| Decision | Recommendation | What the maintainer is accepting |
| --- | --- | --- |
| NE-P1 — native execution trust | Add one **isolated, maintainer-attested native producer**, using the caller's existing Codex authentication and GitHub packet identity. Keep the GitHub Actions profiles unchanged | An authorized maintainer may attest that the approved collector actually executed the named build/cases and retained every applicable attempt. GitHub authenticates the author and statement; it does **not** independently attest local process execution. This is an explicit extension of the current Actions-only trust boundary, limited to the finite isolated Codex pilot. It trusts an honest authorized maintainer; a comment/hash alone is not technical proof of execution |
| NE-P2 — attempt discovery and review | Register each whole producer attempt on the packet PR before native execution; retain one separate completion statement binding its exact committed bundle. Enumerate every registration, and combine completion approval with existing adequacy adoption when practical | Two bounded host records per producer attempt, generated by the command, rather than a signoff for each case. An authorized maintainer approves the concrete execution statement; mapping adoption still requires independent substantive review. Missing/unfinished attempts and contradictory qualifying outcomes remain unverified. A later green attempt cannot erase an earlier one |

These decisions authorize implementation of the mechanism, not live execution, posting a particular
statement, selecting an isolated repository, installing a live profile, approving classification
rows or qualifying evidence. Live runs and GitHub writes retain their explicit invocation approval.
The old API-key-only live-fixture proposal is not adopted. The new producer uses the already
requested environment-supplied authentication; it neither copies a login nor requires a special
API project. Native credential source/intent is recorded without secret bytes or secret digests.

The alternative is to retain Actions-only execution trust and run the native collector inside an
optional approved Actions job with an explicitly configured execution environment. That remains
valid if the maintainer rejects NE-P1, but would require runner/credential arrangements beyond the
portable local command. Re-uploading local files from CI does not meet that alternative. Recommend
the local attested producer to avoid introducing runner infrastructure solely for this pilot.

## Scope and authority

Reuse the existing independent canonical-source and isolated-repository binding. The source-owned
profile must fix repository ids/owner/name, protected source anchor, original installation baseline,
Codex version, acquired target, operations, collectors, case/mapping definitions and trust/review
revisions. Neither a CLI argument, receipt, remote, environment variable nor maintainer comment
chooses or installs that profile. Authors must currently have the existing canonical repository
write/maintain/admin authority, independently resolved through GitHub; names in files are claims.

The existing isolated pilot remains Codex `0.156.1` on the acquired
`x86_64-unknown-linux-musl` target; the GNU wrapper build target is separate metadata. An installed
`0.162.1` smoke cannot qualify it. The approved initial/resume/fork plan has 53 template tuples;
individual classification rows and complete native regimes still require their existing review.
The current public binding implementation admits only the earlier run/CORE shape and has
`LIVE_PROFILE = None`. Extending that finite selection and installing the approved host/profile
are explicit implementation/activation prerequisites, not something this document already enables.
Production enrollment and unsupported-writer refusals retain their existing boundaries.

Native admission needs one narrow target adaptation: revision 1 currently equates both
`Build.host_target` and build `Environment.target` with the obligation target in
`verdict.rs::qualifying`. For native revision 2, independently corroborate those build fields
against the profile's GNU wrapper target, and the obligation/acquisition/runtime identity against
its pinned musl native target. Require the exact approved pair; never relabel a GNU build as musl
to pass the old equality. Preserve revision-1 target checks.

## One foreground attempt

1. **Prepare locally.** Load coherent frozen request/Event/P/O and the independently bound packet
   PR/head. Resolve the approved producer source closure. Build with the existing closed Cargo
   build/provenance helpers; bind actual compiler, graph, locked dependencies, modes and executable
   digests. Keep build environment capture separate from the native authenticated environment.
   An unrelated prebuilt executable or a Git hash printed by the diagnostic is insufficient.
2. **Register before execution.** Produce a bounded canonical plan containing profile/revisions,
   exact packet identity/head, Event/P/O, version/target, source/build identities, context intent and
   requested case population. Store the plan with the existing report payloads. With explicit
   GitHub-write authorization, post one `depth-native-start-v1` fenced record containing those
   discovery keys and its plan digest; re-read it and retain its host id and exact body digest.
   Native probes and SDK calls start only after confirmed registration. A failed or ambiguous
   registration stops execution; do not blindly retry the POST and create a hidden second attempt.
3. **Execute once.** Run the approved cases through production adapters, ordinary caller-provided
   native authentication, owned deadlines and cleanup. Record executed and unrun cases separately,
   bounded sanitized native observations, relevant actual context and before/after changes.
   Preserve failures, cancellations, context refusals and early exits. There is no retry-to-pass.
4. **Retain and review.** Write the finite bundle under
   `cli_manifests/codex/reports/0.156.1/evidence/native-v1/<attempt-key>/` using safe regular files.
   The attempt key is a bounded unique value chosen before registration; it selects storage only.
   Existing packet delivery commits/pushes these proof bytes. Prepare a concrete completion body
   naming the registration, immutable evidence commit, bundle digest and actual executor invocation.
   The maintainer attests execution, reported outcomes, registration ordering and completeness of
   applicable attempts. Post the exact approved `depth-native-finish-v1` statement as a separate
   comment. Independent mapping adoption can share that comment using the existing
   `depth-adequacy-v1` fence; it is a separate assertion, not implied by execution attestation.
5. **Evaluate through owning code.** The host adapter resolves the complete population and obtains
   immutable proof blobs from GitHub, checks coherent current inputs, then supplies private facts
   to the existing evaluator. Generate receipts only after required host references exist.
   Return the existing record-sealed opaque verdict set to authorized isolated consumers.
   Existing acceptance, closeout, separate promotion and protected queue checks still decide writes.

An attempt interrupted after registration remains visible and unverified until its actual outcome
and complete proof can be resolved. Investigating a missing/contradictory attempt does not create a
new generic waiver, reset, latest-green rule or permission to delete it. There is no automated
success attestation on behalf of a human. No host comment is posted in this design turn.

## Minimal retained forms

Reuse revision-1 `Scope`, `Build`, `Cases`, provenance, dependency/environment payloads, mapping,
endorsement and file-reference rules. Use the existing reports tree as the evidence store.
A small bundle index names the canonical plan and every retained payload by path/SHA-256; its
canonical identity excludes itself, receipts and later host endorsements to avoid hash cycles.
The completion binds this index and an immutable evidence commit; the adapter independently reads
all referenced regular blobs, modes and inventories from that commit, then compares current inputs.
A local path or uploaded hash does not replace authenticated source/host resolution.

A **native-only receipt revision 2** keeps the same common top-level members but uses a distinct
strict producer form: `kind = maintainer_native`, repository identity, packet PR, registration id,
completion id and approved collector reference. Both host comment references include their exact
body SHA-256, separate from the committed bundle digest. Preserve the existing revision-1 GitHub Actions
shape/semantics and unknown-field refusals. Dispatch by supported revision/kind into the existing
private evaluator facts; avoid a public trusted-object constructor or a general plugin interface.
The depth record stays revision 1 and continues to reference receipt bytes by path/SHA-256.
Implementation must specify exact JSON forms and limits in the normative contract before coding
admission. Reuse the 1 MiB/4096-entry bounds; raw model/error/auth payloads do not enter the bundle.

The start and finish bodies have distinct types and exact digests. The immutable plan binds all
requested cases and the initial source/context. The bundle adds only actual execution facts.
Receipt/endorsement ids assigned later never participate in the digest they authenticate. A final
receipt is a derived claim: it cannot approve its own producer or broaden the frozen P/O selection.

## Complete population and host checks

The adapter derives the packet PR from the fixed isolated host/request binding, not a receipt.
Paginate the whole packet's comments independently of E's chosen references. Independently
establish canonical maintainer authority before admitting an unreferenced comment into the producer
population. Definitively unauthorized unreferenced copies of start/finish records are chatter,
not registrations or duplicate completions. A selected or previously bound reference whose author
is missing/revoked remains unverified; indeterminate authority lookup is never treated as absent.
Each completion lists applicable registration ids, including prior attempts, through its own
host-observed completion snapshot. Compare that list with that prefix, not future registrations;
a bounded host comment-id watermark in the completion defines the snapshot. Current evaluation
separately includes all subsequently discovered registrations and previously bound ids. Retain ids
bound by earlier completions/current evidence.
This does not recover deleted, never-bound history; NE-P1's honesty limitation below still applies.

Classify authoritative registrations by the full Event/P/O, profile/version/target and applicable
source/context identity. A matching start is applicable **before** inspecting outcome, completion
or proof availability. Bind each registration to at most one authoritative matching completion.
Missing/duplicate/malformed authoritative completions, wrong packet or body, unresolved authority
of a bound record, unknown relevant records, inaccessible proof and unstable/incomplete pagination
remain unverified. Re-read authority, packet/source tips and the discovered population at the end.
Apply finite discovery bounds by refusing excess, not truncating to a favorable subset.

A registration with refused/missing build or context is retained; do not filter it out because a
later attempt has a successful context. Only established scoped applicability can exclude an
unrelated run. Known counterexamples fail; contradictory qualifying pass/fail attempts remain
unverified under the current evaluator. Source/profile/currentness and per-obligation adequacy
remain independently checked even when an authorized maintainer signed the finish statement.

Host comment APIs allow editing/deletion. Exact body digests and referenced host ids detect a
missing/changed referenced record, but cannot prove that an authorized maintainer never deleted an
unreferenced attempt or ran a bypass collector. NE-P1 therefore explicitly trusts the maintainer's
complete-population/execution attestation. This is **not** an append-only audit log or resistance
to a dishonest authorized maintainer. If that trust is unacceptable, choose the Actions alternative;
do not add a signing service or second ledger disguised as comment validation.

## Native context and adequacy remain substantive

Normal authentication does not approve every host plugin, skill, hook, project instruction, model
or config. Qualification requires the exact reviewed native context and actual relevant effective
facts for the claimed operation/regime. Credentials remain with their native resolver; retain only
approved source/presence/intent facts and require the execution environment to keep secrets out of
native diagnostics. Do not trace complete live environment arrays, auth files or authentication
protocol frames into files and redact afterward. Existing offline traces are not live-safe proof.

Capture only source-owned finite nonsecret projections before serialization. Unobservable defaults,
unknown loaders, foreign config/effects, changed binary/transitive launcher or unsupported native
regimes remain unverified. Do not mark `context_complete` from a maintainer statement, source hash,
configuration intent or successful reply. The new producer must define a reviewed context profile
compatible with caller-native authentication; it cannot silently reuse the old cleared-env,
private-home/API-key-only fixture as if the contexts were identical. Required profile facts and
individual assignments need review before a positive native profile is installed.

The twelve current smoke cases may contribute only to the exact reviewed assertions they exercise.
Complete BASE/template/M and initial/resume/fork effect evidence must come from adequate production
path cases, including applicable negative/approval/tool/cleanup regimes. Reuse existing substantive
hermetic cases where valid, with separate provenance; they cannot masquerade as native turns.
Reuse the existing independent counterfactual mapping and exact maintainer adoption. A different
executor/reviewer invocation suffices under the existing policy; no additional mandatory account,
standing role, per-case human signoff or CI status check is introduced.

## Bounded implementation and verification

1. **Admission boundary.** Amend the normative evidence contract after NE-P1/P2 approval; add the
   strict native forms, packet plan/registration/completion resolver and private evaluator adapter.
   Reuse `depth_evidence` predicates, Git input/currentness checks, build graph helpers and opaque
   results. Tests use synthetic comments/Git blobs/fake executables; private positive fixtures prove
   predicates only. The live native profile remains absent until exact host/context/case approval.
2. **Producer and owning-path connection.** Extend the repository-owned foreground collector to
   produce those measured packet-bound inputs, approved case/context coverage and retained outcomes.
   Reuse session checks and sanitization from PR #305. Connect the finite native profile's verdicts
   to existing isolated consumers. Install only source-reviewed, explicitly approved isolated
   profile data; normal CI exercises fake producers without credentials or network/model calls.

Keep each PR reviewable; split a large change by the two concrete boundaries above rather than
creating a general framework or promising all native obligations from the smoke harness. Required
code gates are `make preflight`, default-feature workspace tests, backend type-leak guard and the
three agents' existing manifest/tip/acquisition gates, plus both requested review lanes.
Design validation is Markdown/link/source-reference consistency and both independent reviews.

Minimum admission tests: wrong host/profile/packet/Event/P/O/version/target; stale source/build/
mode/dependency/context; post-hoc or ambiguous registration; unauthorized author; edited/deleted
reference; complete pagination with an unfavorable unselected attempt; missing/unfinished/duplicate
completion; failed or missing cases; mismatched bundle/blob/executable; missing or stale adequacy;
contradictory attempts; unauthorized copied-start/duplicate-finish chatter versus revoked bound
references and unavailable authority lookup; truthful GNU-build/musl-native target pairs and swapped
or mismatched targets; changed-record opaque-verdict refusal; unchanged revision-1 behavior and
production/unsupported-route refusal. A fake host positive is not a live execution endorsement.

Then perform the [real isolated public maintenance chain](support-depth-isolated-proof-plan.md):
acquisition -> P/O -> execution/evidence -> audit -> manual closeout -> separate promotion ->
protected MERGE-queue integration. That proof and later per-agent production authorization remain
separate from approving this design. No fresh smoke, runner service or background job is required
merely to review or implement this proposal.
